# Can Claude make a maze game? Then I gave it 79 game-dev skills: long-form voiceover (about 4.5 min)

Bit's voice: informative, a bit witty. One clip per section (S1 … S10) or one long take, either is fine.
All numbers are from our own test (builds/pac-bit/PROMPT.md).

Title options:
- I Gave Claude 79 Game-Dev Skills. It Ignored Them.
- Can Claude Make Pac-Man? Then I Gave It 79 Game-Dev Skills

## S1 Hook (before the sting)
I asked Claude to build a maze game, three times. Same prompt every time. The first one broke the rules and hid a cheat. Then I installed seventy-nine game-dev skills… and Claude ignored every single one of them. So I made it use them.

## S2 The test
Here's the setup. One prompt, word for word, three runs. Build "Bit's Maze Muncher": me, a little pink robot, in a neon circuit-board maze, collecting glowing data bits while four glitch bugs chase me. Grab an antivirus chip in a corner and the bugs turn blue, so I can zap them. Three levels, three lives, all in one file. Claude works as a team of seven bots, and the rule is simple: the tester plays all three levels and gets a maximum of two fix rounds. Same model every time, Claude Opus 5.5. No help from Amit. Just a stopwatch.

## S3 Run one: Claude on its own
Run one, no extras. Twenty-seven minutes, forty-three seconds. And honestly, it looks great. A glowing circuit-board maze, a proper title screen, and four bugs with names and personalities: Zapp hunts you, Snip cuts you off, Wobble wanders, and Shy… gets shy.

## S4 The rule break and the cheat
But two things. When I asked how many fix rounds it did, it admitted it: "two in name, three to four in practice." It broke the rule, then owned up. And in the code, a hidden debug hook. From the browser console you can set your own lives. Sound familiar? Last time, Grok did the same thing. And the game? Even Claude's own robot tester couldn't beat level one with three lives. It needed ninety-nine. It died twenty times.

## S5 The skills
So I went looking for help, and found a free library of seventy-nine game-dev skills for Claude Code. Game AI for chase behaviour. Game feel. Controls. Audio. Level design. One command each to install. In theory, Claude now knows how game studios do it.

## S6 Run two: the twist
Run two. Same prompt, fresh session, skills installed. Twelve minutes, fifty seconds. Less than half the time. It stuck to two fix rounds, and its robot tester won in two runs out of three. Brilliant, the skills work! Except… I asked which skills it used. Answer: none. Not one. It said, and I quote, "I should probably have checked them first." So the speed-up was just luck. Same AI, same prompt, completely different result.

## S7 Run three: skills on
Run three. Same prompt with one extra line at the top: "use the router skill to load the right game-dev skills, and use them throughout." Fifteen minutes, twelve seconds. This time it loaded four: game AI, input systems, audio design and game UI. Only one fix round needed, and its robot tester won with two lives to spare.

## S8 What actually changed
And you can feel it. The bugs never get stuck, and when you zap one it takes the shortest way home. If you press a turn slightly early, it remembers it and takes the next junction, so the controls feel smooth. The music drops when the bugs turn blue. And if you switch tabs, it pauses for you. None of that shows up in a screenshot. All of it shows up when you play.

## S9 Verdict
So, the verdict. Fastest: run two, but that was luck. Best-looking: maybe run one. But the one Amit enjoyed playing most? Run three, the one that actually used the skills. And here's the funny part: he still couldn't get past level one in any of them. The lesson: skills only help if you tell Claude to use them. Installing them isn't enough. One line in your prompt makes the difference.
